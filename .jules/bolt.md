## 2024-05-18 - Database Flood Control Query Optimization & Address Normalizer Caching
**Learning:** Found that the flood guard check `countLivePending` executes a query matching `tipper_chat_id`, `status`, and `expires_at` on every invoice creation attempt. Since this is on the hot path, a missing index would degrade performance to O(N) linear scan as the `tips` table grows. Adding a composite index `(tipper_chat_id, status, expires_at)` optimizes this check to O(log N). Additionally, user-friendly address formatting is expensive due to the underlying cryptography library (`ton4j` address parsing and base64 rendering). Since the owner wallet is immutable per instance, caching the friendly address inside `CommandHandler` saves CPU cycles.
**Action:** Always verify if database queries on flood guards/indexes contain composite filters and check if expensive, immutable data formatting can be cached.
