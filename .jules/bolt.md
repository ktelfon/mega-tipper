## 2024-11-20 - Composite Index for Stateless DB-Based Flood Guard
**Learning:** This tipping bot is designed to be completely stateless—which is an elegant architecture. Instead of counting active user requests in-memory (which resets on every deploy or restart), the flood-guard uses a query (`countLivePending`) to check if a `tipper_chat_id` has exceeded 3 pending tips. However, because this is run for every single user command or button tap, it is extremely hot. Without a composite index covering `(tipper_chat_id, status, expires_at)`, this check can trigger full table scans or highly inefficient filtering on SQLite/PostgreSQL as the database grows, compromising the stateless design's efficiency.
**Action:** Always verify that hot, stateless queries in the database are backed by specific composite indexes that cover all filtering/conditional columns, avoiding raw table scans under heavy user interaction.
